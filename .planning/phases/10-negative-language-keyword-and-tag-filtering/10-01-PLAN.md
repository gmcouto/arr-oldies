<objective>
**As a** media server administrator,
**I want** arr-oldies to retrieve tag definitions from Radarr and Sonarr instances and map numeric tag IDs to human-readable tag labels on inventory items,
**so that** downstream inventory filtering and reporting can operate on friendly tag names (e.g. "4k", "archive") regardless of internal instance-specific tag ID assignments.

Purpose: Implement the API models, client endpoints, resilient multi-instance fetcher, and correlator dynamic tag label resolution layer required for tag filtering (INVT-09).
Output: Updated constants, API models, Radarr/Sonarr clients, MultiInstanceFetcher, MediaInventoryItem schema, HistoryCorrelator mapping logic, and comprehensive unit test suites.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| *arr API Responses -> Client Deserialization | Parsing untrusted JSON responses from external Radarr/Sonarr instances into Pydantic models |
| MultiInstanceFetcher -> HistoryCorrelator | Aggregated instance data containing potential instance failures or missing tag metadata |

## STRIDE Threat Register

| Threat ID | Category | Component | Description | Mitigation |
|---|---|---|---|---|
| T-10-01 | Denial of Service / Unhandled Exception | `src/arr_oldies/api/fetcher.py` | A single *arr instance failing or timing out on `/api/v3/tag` aborting the entire media library scan | Wrap `client.get_tags()` in try/except blocks inside `fetch_instance_data`, falling back to `tags=[]` gracefully |
| T-10-02 | Data Integrity / Tag Misattribution | `src/arr_oldies/inventory/correlator.py` | Tag ID collisions across different *arr instances (e.g. ID 1 means "4k" in Radarr 1 but "anime" in Radarr 2) | Perform tag ID-to-label resolution per-instance inside `HistoryCorrelator` using instance-specific `tags_by_id` dictionary |
</threat_model>
