<objective>
**As a** media server administrator,
**I want to** specify compound relative time formats such as `1y1m1d` for `--older-than` and `--newer-than` filter options,
**so that** I can accurately target media older than 1 year, 1 month, and 1 day (13 months and 24 hours) without manually calculating the total number of days or months.

Purpose: Upgrade `parse_age_cutoff` in `src/arr_oldies/inventory/parser.py` to tokenize and accumulate compound time duration units (years, months, weeks, days) while maintaining backward compatibility with single unit and bare integer inputs, and verify CLI integration across `scan` and `clean` commands.
Output: Enhanced `parse_age_cutoff` implementation, comprehensive test suite in `tests/test_parser.py`, updated CLI help strings, and integration tests in `tests/test_cli_scan.py` and `tests/test_cli_clean.py`.
</objective>

<task type="auto" id="06-01-01">
<name>Task 1: Extend parse_age_cutoff to support composite time formats and update unit tests</name>
<description>
Update `src/arr_oldies/inventory/parser.py` to support composite duration strings:
1. Handle bare integers (e.g., `30`, `90`) as days.
2. Define supported units and their day multipliers:
   - Years: `y`, `yr`, `yrs`, `year`, `years` -> 365
   - Months: `m`, `mo`, `mos`, `month`, `months` -> 30
   - Weeks: `w`, `wk`, `wks`, `week`, `weeks` -> 7
   - Days: `d`, `day`, `days` -> 1
3. Implement tokenization using regex `([0-9]+)\s*([a-zA-Z]+)` to parse multiple duration tokens in a single string (e.g., `1y1m1d`, `1y 1m 1d`, `2y6m`, `1year 2months 3days`, `3w4d`).
4. Validate that all characters (excluding whitespace, commas, and optional 'and') belong to valid parsed tokens. If any unparsed characters or unknown unit strings exist, raise `ParseError` with a helpful message.
5. In `tests/test_parser.py`, add extensive test cases:
   - Composite combinations (`1y1m1d` -> 396 days, `2y6m` -> 910 days, `3w4d` -> 25 days, `1y2mo3d` -> 428 days).
   - Space-separated, comma-separated, and full-word variations (`1 year 1 month 1 day`, `2 weeks, 3 days`).
   - Case insensitivity (`1Y1M1D`, `2Years 6Months`).
   - Invalid syntax and unknown units raising `ParseError` (`1y2x3d`, `1y1m1d_extra`, `bad_age`, `""`).
</description>
