<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Host Filesystem -> Container Volume Mounts | Host configuration (`config.yaml`) mounted into container at `/app/config.yaml` or `/config/config.yaml` |
| GitHub Actions Runner -> GitHub Container Registry (GHCR) | Multi-arch image build and push authenticated via GitHub Token |

## STRIDE Threat Register

| Threat ID | Category | Component | Description | Mitigation |
|---|---|---|---|---|
| T-09-01 | Elevation of Privilege / Host Compromise | `Dockerfile` | Container running as root (`UID 0`) could allow privilege escalation or accidental file modification on host volumes | Run container strictly under unprivileged `arruser:arrgroup` (`UID 1000, GID 1000`), establish `WORKDIR /app`, create `/config` folder with appropriate non-root ownership, and avoid any root entrypoint execution |
| T-09-02 | Supply Chain Tampering / Credential Exposure | `.github/workflows/release.yml` | Insecure CI/CD permissions or token mismanagement exposing registry credentials or pushing unverified builds | Restrict workflow permissions strictly to `contents: read` and `packages: write`, use ephemeral `${{ secrets.GITHUB_TOKEN }}`, gate container build and push behind passing test suite (`needs: test`), and lock actions to trusted major versions |
</threat_model>

<name>Task 1: Create multi-stage Dockerfile, intelligent entrypoint, and .dockerignore</name>
<description>
1. Create `Dockerfile` with multi-stage build:
   - **Stage 1 (`builder`)**:
     - Base: `python:3.11-slim AS builder`
     - Set `WORKDIR /build`
     - Create virtualenv: `RUN python -m venv /opt/venv`
     - Set `ENV PATH="/opt/venv/bin:$PATH"`
     - Copy `pyproject.toml`, `README.md`, and `src/` directory
     - Upgrade pip and install package: `RUN pip install --no-cache-dir --upgrade pip && pip install --no-cache-dir .`
   - **Stage 2 (`runner`)**:
     - Base: `python:3.11-slim AS runner`
     - Set OCI labels:
       - `org.opencontainers.image.title="arr-oldies"`
       - `org.opencontainers.image.description="CLI tool and auditing engine to inventory and clean stale media across Radarr and Sonarr instances"`
       - `org.opencontainers.image.licenses="MIT"`
       - `org.opencontainers.image.source="https://github.com/gmcouto/arr-oldies"`
     - Set runtime environment variables:
       - `ENV PATH="/opt/venv/bin:$PATH" PYTHONUNBUFFERED=1 PYTHONDONTWRITEBYTECODE=1`
     - Create non-root group and user:
       - `RUN groupadd -g 1000 arrgroup && useradd -u 1000 -g arrgroup -m -d /app arruser && mkdir -p /config && chown -R arruser:arrgroup /app /config`
     - Copy virtualenv from builder stage: `COPY --from=builder /opt/venv /opt/venv`
     - Copy entrypoint script: `COPY docker-entrypoint.sh /usr/local/bin/docker-entrypoint.sh`
     - Make entrypoint executable: `RUN chmod +x /usr/local/bin/docker-entrypoint.sh`
     - Set `USER arruser`
     - Set `WORKDIR /app`
     - Set `ENTRYPOINT ["/usr/local/bin/docker-entrypoint.sh"]`
     - Set `CMD ["--help"]`

2. Create `docker-entrypoint.sh`:
   - Must be an executable POSIX shell script (`#!/bin/sh\nset -e`).
   - If `$1` equals `"arr-oldies"`, shift it (`shift`).
   - If `$#` is 0, or first argument begins with `-` (`"${1#-}" != "$1"`), or first argument is a known subcommand (`"scan"`, `"clean"`, `"validate-config"`):
     - `exec arr-oldies "$@"`
   - Otherwise, fallback to allow direct execution of system commands (e.g., `sh`, `bash`, `python`, `whoami`, `id`):
     - `exec "$@"`

3. Create `.dockerignore`:
   - Exclude development artifacts and caches: `.git`, `.github`, `.venv`, `.pytest_cache`, `.mypy_cache`, `.ruff_cache`, `.planning`, `tests`, `__pycache__`, `*.pyc`, `*.pyo`, `*.pyd`, `*.log`, `.coverage`, `htmlcov/`, `.DS_Store`.
   - Ensure `README.md` and `pyproject.toml` are NOT ignored so `pip install .` succeeds in the build stage.

4. Validate container build and execution locally:
   - Build test container: `docker build -t arr-oldies:test .`
   - Test default help: `docker run --rm arr-oldies:test --help`
   - Test version flag: `docker run --rm arr-oldies:test --version`
   - Test redundant binary prefix: `docker run --rm arr-oldies:test arr-oldies --help`
   - Test subcommand help: `docker run --rm arr-oldies:test scan --help`
   - Test non-root user execution: `docker run --rm arr-oldies:test whoami` (must output `arruser`)
</description>

<name>Task 2: Create GitHub Actions release and CI workflows</name>
<description>
1. Create `.github/workflows/release.yml`:
   - Trigger: `push` on tags matching `'v*'`, plus manual `workflow_dispatch`.
   - Scoped permissions: `contents: read`, `packages: write`.
   - Job `test`:
     - Runs on `ubuntu-latest`.
     - Checks out code with `actions/checkout@v4`.
     - Sets up Python 3.11 with `actions/setup-python@v5` (caching `pip`).
     - Installs `.[dev]`.
     - Runs `ruff check . && ruff format --check .`.
     - Runs `mypy src/`.
     - Runs `pytest`.
   - Job `build-and-push`:
     - Depends on `test` (`needs: test`).
     - Runs on `ubuntu-latest`.
     - Sets up QEMU with `docker/setup-qemu-action@v3` (for ARM64 cross-compilation).
     - Sets up Buildx with `docker/setup-buildx-action@v3`.
     - Logs into GHCR with `docker/login-action@v3` (`registry: ghcr.io`, `username: ${{ github.actor }}`, `password: ${{ secrets.GITHUB_TOKEN }}`).
     - Extracts Docker metadata with `docker/metadata-action@v5`:
       - `images: ghcr.io/${{ github.repository }}`
       - Tags:
         - `type=semver,pattern={{version}}`
         - `type=semver,pattern={{major}}.{{minor}}`
         - `type=semver,pattern={{major}}`
         - `type=raw,value=latest,enable=${{ !contains(github.ref, '-alpha') && !contains(github.ref, '-beta') && !contains(github.ref, '-rc') }}`
     - Builds and pushes image with `docker/build-push-action@v6`:
       - `context: .`
       - `platforms: linux/amd64,linux/arm64`
       - `push: true`
       - `tags: ${{ steps.meta.outputs.tags }}`
       - `labels: ${{ steps.meta.outputs.labels }}`
       - `cache-from: type=gha`
       - `cache-to: type=gha,mode=max`

2. Create `.github/workflows/ci.yml`:
   - Trigger: `push` on `main`, `pull_request` on `main`.
   - Job `lint-and-test`:
     - Runs on `ubuntu-latest` with matrix `python-version: ['3.11', '3.12']`.
     - Checks out code, sets up Python with pip cache, installs `.[dev]`.
     - Runs `ruff check . && ruff format --check .`.
     - Runs `mypy src/`.
     - Runs `pytest`.
   - Job `docker-build-check`:
     - Runs on `ubuntu-latest`.
     - Checks out code, sets up Buildx (`docker/setup-buildx-action@v3`).
     - Builds local test image: `docker/build-push-action@v6` (`context: .`, `load: true`, `tags: arr-oldies:test`).
     - Verifies container execution:
       - `docker run --rm arr-oldies:test --version`
       - `docker run --rm arr-oldies:test --help`
       - `docker run --rm arr-oldies:test arr-oldies --help`

3. Verify workflow YAML validity:
   - Run python script parsing YAML files to ensure syntactically valid YAML and proper indentation.
