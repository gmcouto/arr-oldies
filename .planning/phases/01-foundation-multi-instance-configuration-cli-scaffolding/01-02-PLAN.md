# Plan 01-02: Instance Targeting, Health Prober & CLI Validation Command

Implement instance targeting resolution with conflict detection, concurrent async HTTPX health probing against `/api/v3/system/status`, Rich terminal formatting, and the complete Typer CLI application featuring the `validate-config` command with exit codes 0/1/2.

<threat_model>
## Threat Model (STRIDE / ASVS Level 1)

| Threat ID | Category | Component | Description | Mitigation Strategy |
|---|---|---|---|---|
| T-01-01 | Information Disclosure | `prober.py`, `console.py` | Credential exposure (API keys) in HTTP error traces or terminal logs | Wrap API keys in `SecretStr`, extract only inside `X-Api-Key` header, and mask keys in all console outputs [D-16]. |
| T-01-02 | Security Misconfiguration | `prober.py` | Insecure SSL bypasses on unverified connections | Inherit `verify_ssl` from validated `InstanceConfig` (defaulting to True) in `httpx.AsyncClient` [D-04]. |
| T-01-03 | Denial of Service / Hang | `prober.py` | Unbounded connection hangs against offline or unresponsive instances | Enforce explicit `httpx.Timeout(timeout=instance.timeout, connect=5.0)` per instance to ensure rapid failure detection [D-04, D-08]. |
</threat_model>

<action>
1. Implement `src/arr_oldies/targeting.py`:
   - `resolve_target_instances(config: AppConfig, radarr: bool = False, sonarr: bool = False, instance_names: list[str] | None = None) -> list[InstanceConfig]`:
     - Build lookup dictionary from `config.instances` mapped by lowercased name.
     - Step 1 (Explicit Instance Selection): If `instance_names` is provided (e.g. from `-i / --instance`), lookup each name. If any specified name is not found in configuration, raise `InstanceNotFoundError(f"Instance '{name}' not found in configuration. Available instances: {available_names}")`.
     - If `instance_names` is not provided or empty, select all instances from `config.instances` by default per D-09.
     - Step 2 (Service Flag Filtering & Conflict Enforcement):
       - If `radarr` is True and `sonarr` is False:
         - If `instance_names` was explicitly specified, check if any selected instance has `type != InstanceType.RADARR`. If so, raise `InstanceConflictError(f"Conflicting target flags: Instance '{inst.name}' is Sonarr, but --radarr flag was specified.")` per D-10.
         - Filter candidate list to only instances where `inst.type == InstanceType.RADARR`.
       - If `sonarr` is True and `radarr` is False:
         - If `instance_names` was explicitly specified, check if any selected instance has `type != InstanceType.SONARR`. If so, raise `InstanceConflictError(f"Conflicting target flags: Instance '{inst.name}' is Radarr, but --sonarr flag was specified.")` per D-10.
         - Filter candidate list to only instances where `inst.type == InstanceType.SONARR`.
       - If both `radarr` and `sonarr` are True, or neither is True, retain all currently selected instances.
     - Step 3: If candidate list is empty (e.g. `--radarr` passed but config contains only Sonarr instances), raise `InstanceNotFoundError("No matching instances found for the specified target filters.")`.
     - Return resolved `list[InstanceConfig]`.
2. Create `tests/test_targeting.py` covering:
   - Default behavior targeting all configured instances when no flags passed (D-09).
   - `--radarr` selecting only Radarr instances (CONF-03).
   - `--sonarr` selecting only Sonarr instances (CONF-03).
   - Both `--radarr` and `--sonarr` selecting all instances.
   - `-i / --instance` selecting specific instances by name (repeatable).
   - Unknown instance name raising `InstanceNotFoundError` with available list.
   - Conflicting combinations (`--radarr` + Sonarr instance name, `--sonarr` + Radarr instance name) raising `InstanceConflictError` (D-10).
</action>

### Task 2: Async Concurrent HTTPX Health Prober & Latency Tracker

<read_first>
- .planning/phases/01-foundation-multi-instance-configuration-cli-scaffolding/01-CONTEXT.md (D-05, D-07, D-08, D-16)
- .planning/phases/01-foundation-multi-instance-configuration-cli-scaffolding/01-RESEARCH.md §241-350
- src/arr_oldies/models.py
- src/arr_oldies/constants.py
</read_first>

<action>
1. Implement `src/arr_oldies/prober.py`:
   - `probe_single_instance(instance: InstanceConfig, client: httpx.AsyncClient | None = None) -> ProbeResult`:
     - Construct status endpoint URL: `f"{instance.url}/api/v3/system/status"`.
     - Construct request headers: `{"X-Api-Key": instance.api_key.get_secret_value(), "User-Agent": DEFAULT_USER_AGENT, "Accept": "application/json"}` (D-05, D-16).
     - Construct timeout: `httpx.Timeout(timeout=instance.timeout or DEFAULT_TIMEOUT, connect=DEFAULT_CONNECT_TIMEOUT)`.
     - Record start time via `time.perf_counter()`.
     - Execute async `GET` request.
     - On HTTP 200: Parse response JSON, extract `version = data.get("version", "Unknown")`, calculate `latency_ms = (time.perf_counter() - start) * 1000.0`, return `ProbeResult(instance_name=instance.name, instance_type=instance.type, url=instance.url, success=True, version=version, latency_ms=latency_ms)`.
     - On HTTP 401 / 403: Return `ProbeResult(..., success=False, latency_ms=..., error_message=f"{response.status_code} Unauthorized (Invalid API Key)")` per D-08.
     - On HTTP 404: Return `ProbeResult(..., success=False, latency_ms=..., error_message="404 Not Found (Invalid base URL or endpoint)")`.
     - On other HTTP errors: Return `ProbeResult(..., success=False, latency_ms=..., error_message=f"HTTP {response.status_code}: {response.reason_phrase}")`.
     - Catch `httpx.ConnectError`: Return `ProbeResult(..., success=False, latency_ms=..., error_message="Connection refused / Host unreachable")`.
     - Catch `httpx.TimeoutException`: Return `ProbeResult(..., success=False, latency_ms=..., error_message=f"Connection timed out (> {instance.timeout}s)")`.
     - Catch any other Exception: Return `ProbeResult(..., success=False, latency_ms=..., error_message=f"Network error: {type(exc).__name__}")`.
   - `probe_all_instances(instances: list[InstanceConfig]) -> list[ProbeResult]`:
     - Dispatches concurrent checks using `async with httpx.AsyncClient() as client:` and `asyncio.gather(*(probe_single_instance(inst, client=client) for inst in instances))` per D-07.
2. Create `tests/test_prober.py` using `respx` mocking:
   - 200 OK returning successful `ProbeResult` with version and latency.
   - 401 Unauthorized returning clean error message.
   - 404 Not Found returning clean error message.
   - Connection failure (`httpx.ConnectError`) returning "Connection refused / Host unreachable".
   - Timeout (`httpx.TimeoutException`) returning "Connection timed out".
   - Concurrent execution across multiple mixed-status instances via `probe_all_instances`.
</action>

   - `mask_secret(secret_str: str, visible_prefix: int = 4) -> str`: If length > visible_prefix + 4, return `f"{secret_str[:visible_prefix]}****"`; otherwise return `"****"` per D-16.
   - `render_validation_table(results: list[ProbeResult]) -> Table`: Constructs a `rich.table.Table` with title="Instance Validation Results", box=ROUNDED, header_style="bold cyan", and columns:
     - `Instance` (style="bold cyan")
     - `Type` (style="magenta")
     - `Base URL` (style="blue")
     - `Version` (style="white")
     - `Latency` (style="yellow", formatted as `f"{res.latency_ms:.1f} ms"`)
     - `Status`: If `res.success` is True, render `[bold green]✓ [OK][/bold green]`; if False, render `[bold red]✗ [FAIL][/bold red] [dim]({res.error_message})[/dim]` per D-06.
   - `render_banner() -> None`: Prints styled Rich welcome banner with application title, `__version__`, short description, available commands (`validate-config`, `scan`), and example usage per D-12.
   - `print_error(message: str) -> None`: Outputs `[bold red]Error:[/bold red] {message}` directly to `sys.stderr` using `rich.console.Console(stderr=True)` per D-15.
   - `print_debug(message: str, verbose: bool = False) -> None`: Outputs `[dim][DEBUG] {message}[/dim]` to `sys.stderr` when `verbose=True` per D-15.
2. Implement `src/arr_oldies/cli.py`:
   - Setup `app = typer.Typer(name="arr-oldies", help="Audit and clean stale media across Radarr and Sonarr instances.", no_args_is_help=False, add_completion=False)`.
   - Setup global callback `main_callback(ctx: typer.Context, config: Optional[Path] = typer.Option(None, "--config", "-c", help="Path to config.yaml"), verbose: bool = typer.Option(False, "--verbose", "-v", help="Enable verbose output"), version: bool = typer.Option(False, "--version", help="Show version and exit"))`:
     - If `--version`: prints `f"arr-oldies {__version__}"` and exits with code 0.
     - If `ctx.invoked_subcommand is None`: calls `render_banner()` and exits with code 0 (D-12).
     - Stores `{"config": config, "verbose": verbose}` in `ctx.obj` (D-11).
   - Setup `validate-config` command:
     - `@app.command("validate-config", help="Verify configuration syntax, connectivity, and authentication for all or targeted instances.")`
     - Options: `radarr: bool = typer.Option(False, "--radarr", help="Validate only Radarr instances")`, `sonarr: bool = typer.Option(False, "--sonarr", help="Validate only Sonarr instances")`, `instance: Optional[list[str]] = typer.Option(None, "-i", "--instance", help="Specific instance name(s) to validate (repeatable)")`.
     - Execution flow:
       1. Retrieve `config_path` and `verbose` from `ctx.obj`.
       2. Load config: Call `load_config(config_path)`. On `ConfigError`, call `print_error(str(exc))` and raise `typer.Exit(code=EXIT_CONFIG_ERROR)` (exit code 2 per D-14).
       3. Resolve targets: Call `resolve_target_instances(app_config, radarr=radarr, sonarr=sonarr, instance_names=instance)`. On `InstanceError`, call `print_error(str(exc))` and raise `typer.Exit(code=EXIT_CONFIG_ERROR)` (exit code 2 per D-14).
       4. Async Probe: Run `results = asyncio.run(probe_all_instances(target_instances))`.
       5. Render UI: Render table to `sys.stdout` via `Console().print(render_validation_table(results))`.
       6. Determine Exit Code: If all results have `success == True`, raise `typer.Exit(code=EXIT_SUCCESS)` (exit code 0); if any result has `success == False`, raise `typer.Exit(code=EXIT_PROBE_ERROR)` (exit code 1 per D-13, D-14).

   - `validate-config` with non-existent config file writes error to stderr and exits with code 2.
   - `validate-config` with invalid YAML syntax writes error to stderr and exits with code 2.
   - `validate-config` with non-existent instance name (`-i unknown`) writes error to stderr and exits with code 2.
   - `validate-config` with conflicting flags (`--radarr -i sonarr-tv`) writes error to stderr and exits with code 2.
   - Global option placement flexibility (`arr-oldies --config ... validate-config` and `arr-oldies validate-config --config ...`).
