## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-01 | Information Disclosure | `src/arr_oldies/api/radarr.py`, `src/arr_oldies/api/sonarr.py`, `src/arr_oldies/api/fetcher.py` | high | mitigate | Never include API key in `InstanceFetchResult` or log output; retrieve secret solely in `BaseArrClient` header injection [D-16]. |
| T-02-02 | Denial of Service / Resource Exhaustion | `src/arr_oldies/api/sonarr.py` | high | mitigate | Enforce `asyncio.Semaphore(DEFAULT_SERIES_CONCURRENCY)` (limit: 3 concurrent requests) in `get_all_episode_files` [API-03]. |
| T-02-03 | Availability / Cascade Failure | `src/arr_oldies/api/fetcher.py` | high | mitigate | Use `asyncio.gather(*tasks, return_exceptions=True)` in `fetch_all_instances_data` and encapsulate per-instance exceptions into `InstanceFetchResult(success=False, error_message=...)` [API-04]. |
| T-02-SC | Tampering | npm/pip installs | high | mitigate | Verified packages against registry and locked dependencies. |
</threat_model>

   - `iter_history(page_size, max_pages, event_type)` async generator yielding `RadarrHistoryRecord` sequentially.
   - `fetch_all_history(page_size, max_pages, event_type, progress_callback)` aggregating history with progress callbacks.
